# 水面增强与烟雾隔离

2026-11-14 更新。可选视觉增强，不声明原版光学效果对齐。状态与验收统一见
[TASK-014](../todos/in-progress/TASK-014.md)。设置入口为「水面增强」，默认开启。

桌面运行时配置与自动烘焙见[水面 JSON 配置](water-runtime-config.md)：发布程序直接读取
与再平衡同目录的 JSON，需要生成资源时显示进度并在 Rust 后台自动烘焙。

## 分类依据

液体必须同时匹配关卡、GMDL 对象名和贴图名，并且是无 alpha-test、无 IFL、
无 billboard 的滚动 Blend 批次。普通水面不接入 deform；毒池保留作者化 deform。
不能仅凭 `TextureAnimation + Blend`
判断水体：原版烟雾和云层也满足这两个条件。

`Cylinder01` 的原始顶点法线朝 Z-up，主体是水面；旧法线指南称其为“瀑布帘”不准确。

没有白名单的地图或材质不自动套用增强，也不因名称包含 water/wu 而猜测分类。

## 运行时效果

- 世界坐标双层小斜率波纹，使用有 mipmap 的 128×128 法线数据；确定性的多方向频谱取代少数交叉斜波，避免规则菱形，远处根据像素覆盖率减弱细纹。
- 金华城、四方阵和决死阵的清水表层在加载时按顶点预算细分，运行时叠加 3 组方向、波长和速度均不同的缓慢起伏；
  波相位用低频弯曲打散直线条纹，岸线 2 世界单位内渐弱到原高度。关掉增强立即恢复原顶点位置与法线。
- 六面静态环境探针，带边界采样像素；金华城提高到每面 128×128（390×260 图集），其他液面保持每面 64×64。
  离线对原关卡可见不透明几何求交，采样原贴图和顶点色。探针优先避开桥下；
  未命中建筑或原天空几何的方向记为无反射数据，不生成虚构天空。
- 以适度的正视反射率和随视角变化的 Fresnel 混合原场景静态倒影，按实际场景主光方向计算小高光。
  清水倒影主要采用起伏的几何法线，只混入少量细波法线，保留建筑轮廓的同时让边缘随水扰动。
- 桌面端主菜单设置中增加独立的「水面实时倒影（重启生效）」开关，局内设置不提供此项，默认关闭；启用后从主相机本帧不透明场景颜色和深度中
  查找石墙与人物倒影。射线在深度交点附近细分，找不到或离开屏幕时退回上述烘焙探针；
  毒液、岩浆、烟雾不读取这一路径。Android/WASM 继续使用烘焙探针。
- 桌面端同时启用水面增强和天空增强时，[配置了云倒影的水面](graphics-enhancement-packs.md#水面云倒影)
  按烘焙的地平线判断本地遮挡。Starter 包在金华城为清水配置了 16 个遮挡方向。
  岸线仍随视角透底，开阔水面越接近平视，云影越明显。大尺度水波扭动云的轮廓，细水纹主要影响折射和高光。
  屏幕空间命中的物件优先，静态探针提供建筑轮廓及云缓存未就绪时的回退。云倒影复用现有云全景纹理和更新频率。
- 128×128 水深图由水面向下探测静态不透明场景生成，用于透明度与颜色吸收。
  同一张图的 alpha 通道记录到原水面多边形边界的距离，清水靠岸透出真实河床，
  河心适度遮住重复的高对比河床纹理；不增加一张贴图或一次采样。
  以折射后的水中角度估计路径长度，避免斜视时过度遮蔽；采用低对比青绿色散射色，
  原水 JPG 只参与微弱亮度调节，避免把贴图上的白色波纹当成体积颜色。
  金华城有效水面水底覆盖 100%，原模型河床基本等深；四方阵约 61.7%；
  决死阵无可用不透明水底。缺少水底数据处保留作者化透明度，不虚构深浅。
- 普通水吸收系数为 1.5；金华城约 0.79 世界单位的水深基本恒定。
  河心在正俯视和常见斜视下，倒影混合前河底贡献约为 13% 和 7%；
  岸线附近仍随多边形边界距离增加透底，避免整片水都像覆盖河床纹理的地面。
- 毒液使用绿色散射色、更慢波纹和较弱高光，缺少水底数据时使用显式的视觉浊度，
  不虚构水底。Plane03 的原正弦起伏继续运行，接触检测读取该帧变形后的网格。
- 炼铁狱最上层毒液原本是 SRC_COLOR/ONE 加色混合；只给 Virus02 加低幅度流动法线与绿色波峰，
  保留三层毒液的原混合与不透明底层，不套用清水的透明度/折射/环境倒影，也不把上方毒雾当液面。
- 岩浆沿用原红橙贴图、alpha 遮罩、不透明底层和斜坡形状，增加缓慢明暗变化与局部发亮。
  不套用清水反射/透底，不增加动态光源，也不将烟雾归为岩浆。
- 关闭「水面增强」恢复作者化滚动材质路径；「墙面与地面凹凸」仍为独立设置。

重启并开启桌面实时倒影后，屏幕内可见的不透明人物和建筑可随视角变化；屏幕外区域仍是固定探针近似，
有位置视差。透明特效不进入场景拷贝，也不会每帧从第二机位重新渲染关卡。
人物接触真实液面三角形后触发涟漪：行走留下短轨迹，跨过水面或落水按进入速度增加冲击强度。
普通水的接触点按实际速度和接触范围排开水面；飞沫继承完整的三维接触速度，
水滴按重力下落，落回同一池水时注入较弱的二次波动。脚步较轻、落水较强。
招式接入战斗系统本帧实际武器/身体/特效攻击盒及已裁到场景障碍的投射段；
只有这些几何触到清水三角形才产生冲击，不要求先命中敌人。高空挥刀、桥上攻击、被墙截断的射线不能凭角色附近有水就扬起水花。
相机进入普通水或毒液的实际液面三角形下方时，同一个场景输出通道加入轻微折动与随深度增强的
青绿/毒绿吸收；离开液面或关闭增强后立即恢复，后绘制的 HUD 不染色。岩浆不使用水下视效。
这属于视觉交互，不改变浮力、碰撞、移动、伤害、脚本或网络协议。
2026-11-14 起，清水接触冲量接入二维阻尼波动方程高度场：脚步/落水驱动真实网格高度和法线，
波会传播、叠加并在岸边反射，静止后衰减。岸边截断的冲量保持体积守恒。
局部高度梯度与泡沫通过持久 GPU 纹理上传，直接改变水面法线、倒影和高光；
避免原网格较疏时，小冲击只有几何数据变化却看不见。飞沫使用球面片元重建、软轮廓和厚度相关透光；不再绘制固定皇冠水片或多边形椭球颗粒。
这是水面波动模拟，不包含三维流体、角色浮力或实时平面反射；原水面仍可穿越。

2026-11-14 v3 修订：旧版虽然挂接高度场，但飞沫速度被归一化、跑动强度封顶、
固定冠形水片及过低的飞沫重力让观感失真，用户明确拒绝。现按接触截面和浸入厚度估算排水量，
用速度平方控制可转移的动能，按排水量分配大小不一的细滴，并限制总喷射动能。
速度增大会增加扬起水量、射程和高度，而非把所有水滴放大。慢速涉水保留水面波动，无固定向上初速。
入水保留碰撞前下降速度；武器采样攻击盒角点速度，因此原地旋转/上挑也能传递动量；
第一帧未知速度不再凭空注入 8 单位速度。实体投射物读取实际速度，火铳 hitscan 无飞行时间，
使用小截面的有界冲击代理，不能声称为真实子弹弹道仿真。
喷射转换系数仍为游戏尺度标定的近似，不是三维不可压缩流体求解，观感及帧耗须用户验收。

## 资源与性能边界

资源配置：`meteor_rust/config/water-enhancement.json`；输出：`asset-tools/generated/water/`。
`manifest.json` 记录源 GMB/DES 与使用贴图的 SHA-256、探针位置、有效水底覆盖率和输出哈希。
离线工具只读取 `origin_res/`，不改原包或校验和。桌面运行时从选定游戏资源生成并缓存；
Android / WASM 与自动化夹具继续使用内嵌烘焙图。

金华城因倒影清晰度提高，新增约 542 KiB GPU 纹理；其他普通水/毒液关卡约 251 KiB
（倒影图、水深图、含 mip 的共享波纹法线）。
普通水与毒液 PNG 合计约 145 KiB；岩浆只复用约 85 KiB 波纹法线，不分配反射或水深图。
炼铁狱毒液同样复用共享波纹法线，不增加探针或水深贴图。
加载时建立材质，帧内继续使用现有共享时钟；不新增反射相机或逐帧材质重建。
烘焙路径每像素最多采样一次原贴图、两次波纹、一次倒影、一次水深；岩浆不采样后两者。
桌面「水面实时倒影」的独立开关在启动时读取。含清水的对局按需启用 Bevy 深度预处理与透射通道，
离局或关闭「水面增强」时清理。开启新的深水或浅水预设时，折射也可共用这条通道。
折射取色前检查对应像素的水下深度。开启 MSAA 时使用该像素最近的深度来拦住人物和武器边缘。
折射命中前景时回到水面原位置的透射颜色。
清水表面不参与镜头为露出人物而做的遮挡消隐，避免在水面上挖出露底的圆形缺口。
水面最多进行 8 次粗步进和命中后的 4 次深度细分、一次场景颜色采样，并保留一次烘焙探针采样。
独立开关关闭后撤销深度预处理并恢复静态倒影。此路径有实际 GPU 成本，目标设备帧耗仍需实测。
默认脚步交互跟踪距机位 60 世界单位内最近的 8 名角色，全局最多 24 个事件，寿命 2.2 秒，
正常移动至少间隔 0.18 秒且行进 0.9 世界单位才生成一次；传送不生成落水波。
毒液/岩浆仍采用最多 8 个环带的共享 288 字节 uniform；清水改用局部物理场纹理，不重复叠加装饰环。
招式每帧最多收集 256 个攻击盒和 64 段射线，85 世界单位内最多消费 32 个交点；同一攻击盒节流，静止的活动帧不重复喷水。
普通水的接触飞沫最多对应 24 次触碰，每次最多 256 颗水滴；
绘制最多 2,048 颗（优先较新事件），共享一份透明 mesh，最多 12,288 顶点。
每颗水滴按与人物相同的世界重力（105.84）及与尺寸相关的线性空气阻力推进，落水时结束；
片元球面采用面向视线的投影四边形，世界轨迹、半径、落水时间均独立于镜头。
回落冲量按水滴体积和入水速度计算，每帧最多排入 96 次。
最后一朵飞沫结束时隐藏绘制实体并保留合法网格分配；不向 Bevy 提交零顶点网格。
活跃期间单相机增加一次透明绘制；不新增渲染通道。暂停冻结，关闭增强或换图清除交互状态。
水下视效复用已有的 3D 场景输出 pass；只在相机处于已分类液面下时启用同次采样的轻微 UV 折动和染色，
不新增相机或离屏贴图。默认锐化已启用该 pass；关闭锐化时仅水下临时启用。
每个清水表层最多 24,000 顶点，仍为原水面的一次绘制；每帧只更新位置与法线。
默认高度场每边不超过 512 格、最小间距 0.4 世界单位，固定 120 Hz 子步、最多补 0.1 秒，采用湿区遮罩和无通量岸界；
每池增加至多 1 MiB 的 RGBA8 动态纹理（RG 梯度、B 泡沫），仅脏场上传，活跃区域执行波动求解；
没有扰动时休眠，衰减至阈值后清空。事件绑定表层实体，互不串池；排队冲量在下一次水面更新消费。
暂停冻结，关闭增强清零，换图随实体释放。风浪相位在加载时预计算。毒液、岩浆和烟雾不增加几何。
这些是结构性成本约束，不等于实际设备上零帧耗；大面积水面的帧耗仍需实机测量。

## 生成与自动检查

使用本节的离线工具时，将自己的原版资源目录放在仓库根目录，命名为 origin_res。桌面客户端启动时会自动准备水面缓存。

需要 Python、NumPy、Pillow（见 `asset-tools/tools/water-requirements.txt`）：

```sh
npm --prefix asset-tools run generate:water
npm --prefix asset-tools run verify:water
npm --prefix asset-tools run verify:packs
cargo test --manifest-path meteor_rust/Cargo.toml -p meteor-app --lib stage_material:: -- --test-threads=1
cargo check --manifest-path meteor_rust/crates/meteor-wasm/Cargo.toml --target wasm32-unknown-unknown
```

离线测试检查射线最近命中/未命中、探针六面朝向、波纹斜率与法线长度、静态几何筛选。
Rust 测试核对原关卡白名单、上层水面几何、名义顶点透明度、数据图格式、参数缓冲复用。
离屏 GPU 测试覆盖俯视/掠角的水面变化、动画、开关恢复及滚动非水材质像素不变；
这些自动化不等于游戏实机观感或性能验收。

## 用户实机验收

1. 重新构建/启动后进入金华城河边，固定机位切换「水面增强」，分别俯视和低角度观察。
   在菜单开启「水面实时倒影」并重启进程后，岸墙和水边人物应在水中出现随视角变化的倒影；
   人物移动时倒影同步移动。关闭该开关并重启后回到静态探针；关闭水面增强仍立即恢复原滚动贴图。
2. 四方阵同时看下方水面、wu 烟雾和瀑布，切换增强：水面变化，烟雾/瀑布保留原表现。
   金华城 Sphere02/03 云层也不应出现波纹、高光或水深变色。
3. 决死阵观察 Plane37 上层水面：只有一层增强倒影，没有上下双层闪烁。
4. 同一设备、地图、机位、分辨率和画质，预热后分别记录静态探针与实时倒影的平均帧耗和慢帧；
   补测水面占满屏幕、沿岸转动镜头和多人战斗。若有持续帧耗回退，附设备和采样数据再调预算。
5. 在金华城河中行走、跑动、停步和跳落。脚下应有轻微飞沫与短涟漪轨迹；
   跳落后应出现更明显但不闭合的飞沫、短水滴及扩散波，停步后约 2 秒消散。
   靠岸低机位观察水面：细纹不应形成规则菱形，河内应有可辨识的缓慢上下起伏，
   与岸线接触处不应出现周期性穿模；关闭增强应回到原平面。
   在桥上、干岸边重复，不能隔空触发。暂停后波纹冻结，换图后无残留；本地和远端角色均参与。
6. 在毒牙阵与炎硫岛切换增强：毒液保持绿色且有起伏；岩浆保持红橙和原有流道；
   毒雾/烟雾不出现液体高光。进入液体仍按原伤害逻辑处理；无需为了验收停留在危险区域。
7. 炼铁狱观察绿色毒液、上方毒雾和流动特效：开关仅改变最上层 Virus02 的波纹，
   下层/雾/特效维持原貌。让相机短暂进入普通水和毒液液面下，再移出并关闭增强：
   水下应出现柔和的青绿或毒绿视效，HUD 保持原色；离开或关闭后立即消失。
